# Практическое задание 9. Асинхронность и корутины в Kotlin

## Задание 1. Отмена установки приложения

**Реализация**

- В `AppDetailsState.Content` добавлено поле `installState: InstallState` с состояниями:
  `NotInstalled`, `Installing(progress)` (0..100), `Installed`.
- В `AppDetailsViewModel` хранится `installJob: Job?`. В `onInstallClick()`:
    - если установка уже идёт — `installJob?.cancel()`, состояние сбрасывается в `NotInstalled`;
    - иначе запускается корутина: `installJob = viewModelScope.launch { emulateInstall() }`.
- `emulateInstall()` — цикл прогресса 0..100 с шагом 5, каждые 150 мс (`delay(150)`)
  состояние обновляется атомарно через `_state.update { }`, в конце выставляется `Installed`.
- Кнопка показывает «Отменить», пока `installState is InstallState.Installing`, иначе «Установить».

**Как работает отмена и structured concurrency**

- `Job.cancel()` не останавливает корутину мгновенно: при достижении ближайшей точки
  приостановки (`delay`) выбрасывается `CancellationException`, и корутина завершается.
- Состояние при отмене сбрасывается в `NotInstalled`, повторное нажатие запускает установку заново.
- Корутины запущены в `viewModelScope`: при уничтожении ViewModel все его корутины
  отменяются автоматически — дочерние корутины не переживают родителя (structured concurrency).

**Проверено вручную:**
- [x] установка идёт с прогрессом, кнопка меняется на «Отменить»;
- [x] отмена в середине установки сбрасывает прогресс;
- [x] после 100% появляется состояние «Установлено»;
- [x] выход с экрана и повторное открытие сбрасывают состояние.

## Задание 2. Загрузка рейтингов в каталоге

**Реализация**

- `CatalogApi.getRating(id: Int): Float` — эмуляция сетевого запроса: `delay(1500)`,
  возвращает рейтинг 3.0–5.0.
- В `AppsRepository` два способа загрузки, время замеряется через `measureTimeMillis`:
    - `loadRatingsSequentially` — обычный `for`: каждый запрос стартует только после
      завершения предыдущего;
    - `loadRatingsInParallel` — все запросы стартуют одновременно:
      `coroutineScope { ids.map { id -> async { id to getRating(id) } }.awaitAll() }`.
- Вызов через две кнопки на экране каталога; время показывается на экране,
  рейтинги выводятся звёздочкой на карточке приложения.

**Замеры на списке из 11 приложений**

| Способ загрузки | Время |
|---|---|
| Последовательно | 16523 мс |
| Параллельно | 1505 мс |

**Выводы**

- Последовательная загрузка: время растёт линейно от количества запросов —
  ~1.5 с × 11 ≈ 16.5 с, каждый запрос ждёт завершения предыдущего.
- Параллельная загрузка: все запросы выполняются одновременно, поэтому общее время
  ≈ времени одного запроса (~1.5 с) и почти не зависит от количества приложений.
- Ускорение в замере: примерно в 11 раз.
- Параллельный запуск через `async` безопасен: все корутины живут в общем скоупе —
  `coroutineScope` дождётся всех дочерних корутин и пробросит исключение, если
  какой-то запрос упадёт (structured concurrency).
